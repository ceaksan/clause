# ADR-001: herdr multi-workspace observer board

**Date:** 2026-11-07
**Status:** Accepted
**Spec:** [2026-11-07-clause-herdr-board-design](../superpowers/specs/2026-11-07-clause-herdr-board-design.md)

## Context

Clause was built as a single-session scratchpad for one Claude Code session: one global
`Session` set through `set_session`, one note list, one JSON file per session. The user now
runs several agents in parallel inside herdr. Agents pass decision topics to each other
through herdr, and those topics scroll away in terminals the user is not watching. With the
old model, a second agent calling `set_session` replaced the first agent's view.

## Decision

Clause becomes a one-way observer board for the user.

- `clause-mcp` derives an `AgentContext` from `HERDR_WORKSPACE_ID` and `HERDR_PANE_ID`
  (fallback `local` / `pid-<pid>` outside herdr), resolves display labels through the
  `herdr` CLI with a 2 s timeout per call, and attaches the context to every IPC request.
  `set_session` is removed; protocol version becomes 2.
- The app keeps one flat note list. Every agent request is scoped to the caller's
  `(workspaceId, paneId)`; the UI is unscoped.
- A `decision` note type with status `sent` or `decided`. Type and status invariants are
  enforced in the model; status on a non-decision is rejected at the IPC boundary.
- Each pane keeps its 5 most recent decided decisions; older ones are pruned.
- One snapshot file, `~/.clause/board.json`, replaces per-session files.
- The panel groups by workspace, then pane, with labels next to IDs.
- swift-sdk is pinned by revision to tag 0.12.1 (`a0ae212`). 0.11.0 does not compile with
  Xcode 27.1 (NetworkTransport data race, fixed upstream in 0.12.0), and 0.12.x cannot be
  resolved through a version range because it depends on `swift-docc-plugin` by branch.
  Confirmed by the user 2026-11-07.

## Consequences

### Positive
- Any number of agents across workspaces write concurrently without clobbering each other.
- Agents need no setup call; identity comes from the environment.
- An agent's tool output only contains its own pane's notes.
- The board stays small without manual cleanup of decided topics.

### Negative
- Breaking protocol change: an old `clause-mcp` binary cannot talk to the new app.
- `add_note` can wait up to about 4 s when herdr hangs (two sequential lookups).
- Scoping is not authentication; any local process as the user can claim any context.
- Pane ID uniqueness across herdr restarts is unverified.
- The board is only useful if agent instruction files tell agents to post; that rollout is
  outside this repository.

### Alternatives Considered
- Keeping swift-sdk at `from: "0.11.0"`: ClauseMCP does not build on the current Xcode.
- herdr plugin pane instead of the Swift window: keeps everything in the terminal, but the
  floating window stays visible outside herdr and already exists.
- SQLite store: needed only for durable history, which is a non-goal.
- Owner / from / to fields on decisions: the user only needs to see where a topic lives in
  order to ask that agent; routing fields would turn the board into a task system.
- Agents reading the board to coordinate: herdr already carries agent-to-agent messages;
  a second channel invites drift and cross-agent prompt injection.
